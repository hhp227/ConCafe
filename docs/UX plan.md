# 🎀 ConCafe UI 구조 설계 문서

## 📱 1. 하단 탭 구조 (Bottom Navigation)
[홈]  [탐색]  [체크인]  [랭킹]  [내 정보]

### 메인 네비게이션 노출 규칙
- 게스트 또는 일반 유저(`VISITOR`) 로그인 상태:
  - [홈] [탐색] [체크인] [랭킹] [내 정보]
- 캐스트(`CAST`) 로그인 상태:
  - [홈] [탐색] [팬관리] [랭킹] [내 정보]
- 카페 운영자(`CAFE_OWNER`) 로그인 상태:
  - [홈] [탐색] [카페관리] [랭킹] [내 정보]
- 관리자(`ADMIN`) 로그인 상태:
  - [홈] [탐색] [운영관리] [랭킹] [내 정보]

### 역할별 탭 치환 원칙
- 세 번째 메인 탭은 기본적으로 `체크인` 영역이다.
- 로그인한 사용자 역할이 `CAST`이면 `체크인` 탭 대신 `팬관리` 탭을 노출한다.
- 로그인한 사용자 역할이 `CAFE_OWNER`이면 `체크인` 탭 대신 `카페관리` 탭을 노출한다.
- 로그인한 사용자 역할이 `ADMIN`이면 `체크인` 탭 대신 `운영관리` 탭을 노출한다.
- 게스트와 일반 유저는 항상 `체크인` 탭을 사용한다.
- 한 계정에 여러 역할이 공존하는 경우 우선순위는 `ADMIN > CAFE_OWNER > CAST > VISITOR`로 적용한다.

# 1️⃣ 🏠 홈 (Home)

### 목적
- 앱 진입 시 첫 화면
- 관심 메이드 & 인기 정보 노출

### UI 구성
- 상단: 로고 + 알림 아이콘
- 🎀 홈 프로모션 배너 (상단 캐러셀)
- 🔥 이번 주 인기 메이드 (가로 스크롤 카드)
- 📍 근처 메이드카페 (지도 미리보기 또는 카드 리스트)
- 🎂 생일인 메이드
- 📢 카페 공지 (최근 3개)

### 홈 배너 노출 정책
- 홈 상단에는 프로모션 배너를 캐러셀 형태로 노출한다.
- 동시에 노출되는 활성 배너는 최대 3~5개로 제한한다.
- 배너마다 노출 시작일과 종료일이 있으며, 현재 시간이 노출 기간 안에 있을 때만 홈에 표시된다.
- 활성 배너 슬롯이 모두 찬 상태에서는 신규 배너를 즉시 게시할 수 없고 예약 등록만 가능하다.
- 예약 배너는 기존 활성 배너 종료 이후 순차적으로 노출된다.

### 홈 배너 등록 권한
- 관리자(`ADMIN`)는 전체 홈 배너를 등록/수정/중지할 수 있다.
- 카페 운영자(`CAFE_OWNER`)는 본인이 운영 권한을 가진 카페 관련 배너를 등록할 수 있다.
- 일반 유저와 캐스트는 홈 배너를 등록할 수 없다.

### 홈 배너 카드 요소
- 배너 이미지
- 제목
- 서브 문구
- 연결 대상 (카페 상세 / 이벤트 / 외부 링크 등)
- 노출 기간
- 등록 상태 (`DRAFT`, `SCHEDULED`, `ACTIVE`, `ENDED`, `PAUSED`)

# 3️⃣ 📍 체크인

### 메인 화면
- 현재 위치 기반 카페 지도
- 오늘 방문한 카페
- + 방문 추가 버튼
- 최근 방문 타임라인

### 공통 지도 원칙
- 체크인 탭의 지도는 로그인 여부와 관계없이 공통으로 노출한다.
- 비로그인 상태에서는 지도 탐색과 카페 상세 진입만 허용한다.
- 로그인 상태에서는 같은 지도를 유지한 채 실제 체크인 액션과 방문 기록 기능을 확장한다.
- 즉, 로그인 여부에 따라 사라지는 것은 지도가 아니라 `체크인 가능 범위`다.

### 체크인 플로우
1. 카페 선택
2. 날짜 선택
3. 위치 인증 (100m 반경)
4. 메모 작성
5. 등록

### 노출 대상
- 게스트
- 일반 유저(`VISITOR`)

### 체크인 탭 - 비로그인 사용자 화면

#### 목적
- 로그인하지 않은 사용자도 ConCafe의 핵심 콘텐츠인 메이드 카페 정보를 계속 탐색할 수 있도록 한다.
- 체크인 기능은 로그인 후에만 사용할 수 있도록 제한하되, 공통 지도와 인기 카페/캐스트 정보는 자유롭게 확인 가능해야 한다.

#### 화면 구성
- 비로그인 상태에서 체크인 탭에 진입하면 아래 UI를 표시한다.
- 단, 상단 지도 영역은 로그인 상태에서도 동일한 구조를 유지한다.

##### (1) 카페 지도 (Map)
- 현재 위치 기반 지도를 표시한다.
- 주변 메이드 카페 위치를 마커로 표시한다.
- 마커를 탭하면 카페 상세 화면으로 이동할 수 있다.
- 지도 내 `체크인` CTA를 누르면 로그인 유도 BottomSheet를 노출한다.

##### (2) 인기 메이드 카페 섹션
- 제목: `🔥 인기 메이드 카페`
- 표시 정보:
  - 카페 이름
  - 위치
  - 평점
  - 총 체크인 수
- 정렬 기준:
  - `checkinCount` 내림차순
- 표시 개수:
  - 최대 10개

##### (3) 인기 캐스트 섹션
- 제목: `☕ 오늘 인기 캐스트`
- 표시 정보:
  - 캐스트 프로필 이미지
  - 캐스트 이름
  - 오늘 방문 수
- 정렬 기준:
  - `todayVisit` 내림차순
- 표시 개수:
  - 최대 10명

##### (4) 로그인 유도 영역
- 문구:
  - `로그인하고 메이드카페 방문을 기록해보세요!`
- 혜택 안내:
  - 방문 기록 저장
  - 카페 팬 레벨 상승
  - 체크인 배지 획득
- 버튼:
  - 로그인
  - 회원가입

#### 기능 제한
- 비로그인 사용자 가능 기능
  - 지도 탐색
  - 카페 정보 보기
  - 캐스트 정보 보기
  - 인기 카페 확인
- 비로그인 사용자 제한 기능
  - 체크인
  - 리뷰 작성
  - 좋아요
  - 팬 레벨

#### 로그인 유도 BottomSheet
- 비로그인 사용자가 체크인 버튼을 누르면 로그인 유도 BottomSheet를 표시한다.
- 메시지:
  - `체크인하려면 로그인이 필요합니다.`
- 버튼:
  - 로그인하고 체크인
  - 회원가입

### 체크인 탭 - 로그인 사용자 화면 방향
- 로그인 상태에서도 체크인 탭 상단에는 동일한 지도 영역을 유지한다.
- 로그인 사용자는 지도에서 카페를 탐색한 뒤 실제 체크인 플로우로 진입할 수 있다.
- 인기 메이드 카페 / 인기 캐스트 섹션은 유지하거나 하단 보조 섹션으로 재배치할 수 있다.
- 오늘 방문 / 최근 타임라인은 지도 아래에서 확장 정보로 노출한다.

# 3-2️⃣ ☕ 카페관리

### 목적
- 카페 운영자가 카페 운영 데이터를 관리하는 전용 탭

### 메인 화면
- 내 카페 목록
- 선택한 카페의 운영 대시보드
- 공지/이벤트 관리
- 홈 배너 관리
- 메뉴/굿즈 관리
- 캐스트/출근표 관리

### 데이터 로딩 원칙
- 카페관리 화면 데이터는 화면별 하드코딩 상태가 아니라 `GetCafeManagementUseCase`를 통해 가져온다.
- `GetCafeManagementUseCase`는 `CafeManagementRepository`를 통해 운영 카페 목록, 검색 가능한 카페 목록, 운영자 신청 상태를 함께 조합한다.
- `CafeManagementRepository`는 `ConCafeDataSource`를 원천 데이터로 사용하고, Repository 내부에 화면용 리스트를 별도 하드코딩하지 않는다.

### 메뉴/굿즈 관리 상태 원칙
- 메뉴 판매 상태는 `cafes/{cafeId}/menus/{menuId}.isAvailable` 필드를 소스 오브 트루스로 사용한다.
- 굿즈 판매 상태는 `cafes/{cafeId}/goods/{goodsId}.stock` 값으로 판단하며 `stock > 0`이면 판매 중, `0`이면 품절로 본다.
- `메뉴&굿즈 관리` 목록 화면과 편집 화면은 동일한 공용 모델 기준으로 상태를 표시해야 한다.
- 메뉴 추가/수정 저장 시 이름, 가격, 설명, 카테고리와 함께 `isAvailable` 값도 저장한다.
- 굿즈 추가/수정 저장 시 이름, 가격, 이미지, 재고 상태를 함께 저장하며 재고 상태는 `stock`으로 환산한다.

### 다중 카페 운영 UX 원칙
- 카페 운영자가 여러 카페를 운영할 수 있으므로 탭 진입 시 먼저 `내 카페 목록`을 노출한다.
- 운영 카페가 1개인 경우에는 목록을 스킵하고 바로 해당 카페의 대시보드로 진입할 수 있다.
- 운영 카페가 2개 이상인 경우에는 카페 선택 후 해당 카페 컨텍스트로 관리 화면을 연다.
- 카페 전환은 상단 드롭다운 또는 `카페 변경` 액션으로 지원한다.
- 연결된 운영 카페가 0개인 경우에는 `카페관리 Empty State`를 노출한다.

### 카페관리 Empty State
- 제목: `아직 연결된 운영 카페가 없습니다`
- 설명: `기존 카페를 검색해 운영 권한을 신청하거나 새 카페를 등록하세요`
- 버튼:
  - 기존 카페 검색
  - 새 카페 등록
- 보조 문구:
  - `운영자 신청은 관리자 승인 후 반영됩니다`

### 기존 카페 검색 화면
- 검색바: 카페명 / 지역 / 주소
- 필터: 국가 / 도시
- 검색 결과 카드:
  - 대표 이미지
  - 카페 이름
  - 지역
  - 승인 상태
  - `이 카페 운영자 신청` CTA

### 운영자 신청 BottomSheet 또는 상세 화면
- 선택한 카페명 확인
- 운영자 신청 메시지 입력
- 운영 증빙 이미지 업로드
- 제출 버튼

### 신청 상태 카드
- `승인 대기 중` 상태 배지
- 신청한 카페 이름
- 신청일
- 처리 안내 문구
- 승인 완료 시 `내 카페 목록으로 이동` 또는 자동 진입
- 반려 시 재신청 CTA 노출 가능

### 내 카페 목록 화면
- 카페 카드 리스트
- 카드 항목: 대표 이미지 / 카페 이름 / 지역 / 승인 상태 / 오늘 체크인 수 요약
- 카드 탭 시 선택한 카페의 관리 대시보드로 이동

### 카페 대시보드 화면
- 오늘 방문자
- 오늘 체크인
- 오늘 리뷰
- 평점
- 빠른 이동: 캐스트 관리 / 출근표 / 이벤트 / 카페 설정 / 홈 배너 관리

### 카페 정보 수정 화면
- 진입 위치: `카페 대시보드 > 카페 정보 관리`
- 초기값:
  - 카페명
  - 카페 소개
  - 대표 이미지
  - 갤러리 이미지
  - 지역 / 주소
  - 연락처
  - 영업시간
- 데이터 로딩:
  - 화면 초기값은 `GetCafeDetailUseCase`를 통해 가져온다.
  - 별도 화면 하드코딩 초기값은 두지 않는다.
- 저장:
  - 저장 버튼 클릭 시 `UpdateCafeInfoUseCase`를 호출한다.
  - 저장 성공 시 카페 상세 화면과 운영 화면에서 즉시 동일 데이터가 보여야 한다.
  - 저장 성공 피드백은 플랫폼 기본 UX를 따른다.
    - Compose: 스낵바
    - iOS: alert
- 플레이스홀더로 유지 가능한 항목:
  - 대표 이미지 업로드
  - 갤러리 이미지 추가
  - 지도 핀 위치 조정
  - 예외 영업일 관리

### 홈 배너 관리 화면
- 배너 목록 탭: `진행중`, `예약`, `종료`
- + 배너 등록 버튼
- 각 배너 카드에 썸네일, 제목, 노출 기간, 상태, 연결 대상 표시
- 슬롯 초과 상태에서는 등록 버튼 클릭 시 `즉시 게시 불가 / 예약 등록만 가능` 안내 노출
- 현재 선택한 카페 기준으로 연결 가능한 대상만 노출한다.

### 카페 운영자 배너 등록 플로우
1. 배너 이미지 업로드
2. 제목 / 서브 문구 입력
3. 연결 대상 선택 (선택한 카페 상세 / 이벤트 / 공지 / 외부 링크)
4. 노출 시작일 / 종료일 선택
5. 저장
6. 활성 슬롯 여유가 있으면 `ACTIVE`, 없으면 `SCHEDULED`로 등록

### 노출 대상
- 카페 운영자(`CAFE_OWNER`)

# 3-3️⃣ 🛠 운영관리

### 목적
- 관리자가 승인/반려/운영 상태를 처리하는 전용 탭

### 메인 화면
- 카페 승인 대기 목록
- 운영자/캐스트 Claim 승인
- 홈 배너 운영 관리
- 신고/밴 관리
- 전체 운영 현황

### 관리자 배너 운영 화면
- 전체 배너 현황 보드: `초안`, `진행중`, `예약`, `종료`, `중지`
- 등록 주체 필터: `전체`, `관리자`, `카페 운영자`
- 노출 기간 겹침 여부와 남은 슬롯 수 확인
- 배너 강제 중지 / 수정 / 우선순위 조정 가능

### 관리자 배너 등록 플로우
1. 배너 유형 선택 (플랫폼 공지 / 이벤트 / 제휴 프로모션 / 카페 홍보)
2. 배너 이미지 및 문구 입력
3. 연결 대상 설정
4. 노출 기간 설정
5. 저장
6. 현재 활성 배너 수를 기준으로 `ACTIVE` 또는 `SCHEDULED` 상태 자동 지정

### 노출 대상
- 관리자(`ADMIN`)

- 현재 단계에서는 설정 데이터 저장 없이 화면만 추가한다.

#### 데이터 조합 규칙
- 카페 상세 화면은 `GetCafeDetailUseCase`가 상세/메이드 출근 여부/리뷰/사용자 닉네임/방문인증 여부/즐겨찾기 상태를 조합한다.
- 즐겨찾기 토글은 `ToggleFavoriteCafeUseCase`를 통해 처리한다.
- 메이드 출근 여부는 `CastDetail.schedule`의 당일 스케줄 존재 여부로 계산한다.
- 카페 소개, 메이드 소개, 메뉴 설명 문자열은 공통 모델의 `desc` 필드를 사용한다.
- 비로그인 상태에서 즐겨찾기 시도 시 로그인 화면으로 라우팅한다.

# 🏪 Multi-Cafe Owner 구조 설계

ConCafe에서는 하나의 카페 운영자가 여러 카페를 운영할 수 있다.

예시

Owner A
- Maid Dream Tokyo
- Seoul Maid Cafe
- Akihabara Butler Cafe

따라서 Owner와 Cafe의 관계는 다음과 같다.

Owner (1) → Cafe (N)

### Firestore 구조

users/{userId}

- role: VISITOR | CAST | CAFE_OWNER | ADMIN
- ownedCafeIds: [cafeId]

cafeOwnerClaims/{claimId}

- userId
- cafeId
- status
- message
- evidenceImageUrls[]
- reviewedAt

cafes/{cafeId}

- name
- description
- ownerIds: [userId]
- createdAt
- approved

ownerIds는 여러 운영자를 지원하기 위해 배열 구조로 설계한다.

예시

cafes/{cafeId}

- ownerIds:
  - ownerA
  - ownerB

이 구조는 공동 운영이나 지점 관리 상황에서도 유연하게 동작한다.

### UX 적용 원칙

- 카페 운영자는 앱 진입 후 자신이 관리하는 카페 목록을 먼저 확인한다.
- 운영 카페가 여러 개여도 하단 탭은 하나의 `카페관리` 탭만 사용한다.
- 세부 관리 기능은 선택된 카페 컨텍스트 안에서 동작한다.
- 연결된 운영 카페가 없을 경우에는 기존 카페 검색 또는 신규 카페 등록을 유도하는 빈 상태 화면을 사용한다.

# 📱 카페 운영자 전용 탭 UX 설계

ConCafe 하단 네비게이션 3번째 탭은 사용자 역할에 따라 다르게 표시된다.

일반 사용자

- 탭 이름: Check-in

카페 운영자

- 탭 이름: Cafe Manage

### 역할별 탭 해석

- 일반 사용자에게는 기존 `체크인` 탭을 유지한다.
- 카페 운영자에게는 3번째 탭을 `Cafe Manage`로 치환한다.
- 다중 카페 운영 여부는 탭 수가 아니라 탭 내부의 정보 구조로 해결한다.
