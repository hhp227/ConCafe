## 0. 목표/범위
- [ ] MVP 목표 확정: 메이드 중심 팬 플랫폼 + 위치 인증 기반 신뢰 리뷰
- [ ] MVP 화면 범위 확정: 홈/탐색/체크인/랭킹/마이 + 카페/메이드 상세
- [ ] 제외 범위 확정: Admin 웹 콘솔, 수익화 기능(2~3차로 이관)

## 0-1. 인증 UX 고정 정책 (기획 정합)
- [ ] 앱 첫 실행 기본 진입 화면은 로그인 화면이 아닌 홈 화면으로 고정
- [ ] 비로그인 상태(게스트)에서도 홈/탐색/상세 조회는 가능
- [ ] 마이 페이지 진입 시 비로그인 상태면 로그인 화면으로 라우팅
- [ ] 로그인 성공 후 앱 재실행 시 세션 유지(자동 로그인)
- [ ] 로그아웃 시에만 세션 초기화 및 마이 페이지 재진입 시 로그인 요구

## 0-2. 로그인 필요 기능 매트릭스 (전면 반영)
- [ ] 게스트 가능: 홈/탐색/카페 상세/메이드 상세/랭킹 조회
- [ ] 로그인 필요: 마이 페이지 진입, 프로필 수정
- [ ] 로그인 필요: 즐겨찾기 토글, 메이드 팔로우/언팔로우
- [ ] 로그인 필요: 체크인 생성, 리뷰 작성/삭제, 리뷰 좋아요
- [ ] 로그인 필요: 알림 조회/읽음 처리
- [ ] 로그인 필요 기능에서 비로그인 접근 시 로그인 화면으로 라우팅
- [ ] 로그인 성공 시 원래 시도한 기능/화면으로 복귀

## 1. 사전 의사결정(필수)
- [ ] `conceptType` enum 확정 (`MAID|BUTLER` vs 확장형)
- [ ] `events` 저장 위치 확정 (루트 `events` 또는 `cafes/{cafeId}/events`)
- [ ] `favorites`/`visitHistory` 저장 방식 확정 (배열 vs 서브컬렉션)
- [ ] 랭킹 점수식 확정 (팔로우/리뷰 언급/인증 방문 가중치)
- [ ] 리뷰/프로필 이미지 업로드 용량·해상도 정책 확정

## 2. 아키텍처 WBS
- [ ] 모듈 책임 고정: `composeApp`(UI), `shared`(도메인/유스케이스)
- [ ] 레이어 구조 정의: Presentation / Domain / Data
- [ ] Repository 인터페이스 목록 정의
- [ ] 에러 모델/결과 모델 통일 (`Success/Failure` 정책)
- [ ] 공통 상태 관리 패턴(MVI) 정의 (`uiState`, `event`, `action`)

## 3. 데이터/백엔드 WBS
- [ ] Firestore 컬렉션 생성 기준 문서 확정
- [ ] 핵심 인덱스 생성
- [ ] 인증/권한 룰 초안 작성
- [ ] Cloud Functions 목록 확정
- [ ] Storage 경로 규칙 정의 (카페/메이드/리뷰 이미지)

### 3-1. 인덱스 체크리스트
- [ ] 카페 탐색: `approved + region + ratingAvg`
- [ ] 카페 최신순: `approved + createdAt`
- [ ] 리뷰 정렬: `cafes/{cafeId}/reviews(createdAt desc)`
- [ ] 출근표: `castSchedules(cafeId + date)`
- [ ] 출근표: `castSchedules(castId + date)`

### 3-2. 서버 검증 체크리스트
- [ ] 리뷰 작성 전 `verified visit` 존재 검증
- [ ] 체크인 시 반경 100m 위치 검증
- [ ] 평점 평균/리뷰 수 집계 원자적 업데이트
- [ ] 팔로워 수/랭킹 점수 집계 업데이트

## 4. 보안/권한 WBS
- [ ] `ADMIN`, `OWNER`, `USER` 역할 정책 문서화
- [ ] USER 쓰기 범위 제한 검증 (본인 데이터만)
- [ ] OWNER 수정 범위 제한 검증 (본인 cafe만)
- [ ] ADMIN 승인/반려/밴 권한 검증
- [ ] 승인되지 않은 카페 노출 제한 검증

## 5. 기능 구현 WBS (MVP)

### 5-1. 인증/프로필
- [ ] 게스트 세션 + 로그인 플로우
- [ ] 프로필 조회/수정
- [ ] 로그인 사용자 초기 데이터 생성
- [ ] 세션 복원(앱 재실행 자동 로그인)

### 5-2. 홈 탭
- [ ] 인기 메이드 섹션
- [ ] 근처 카페 섹션
- [ ] 생일 메이드 섹션
- [ ] 최신 공지 3개 섹션

### 5-3. 탐색 탭
- [ ] 검색바
- [ ] 지역 필터(KR/JP/도시)
- [ ] 정렬(인기/최신/평점)
- [ ] 내부 탭(카페/메이드)

### 5-4. 카페 상세
- [ ] 상단 이미지 슬라이더/기본 정보
- [ ] 탭: 정보/메이드/메뉴/리뷰/공지
- [ ] 즐겨찾기 토글(비로그인 시 로그인 라우팅)

### 5-5. 메이드 상세
- [ ] 프로필/소개/소속 카페
- [ ] 팔로우 버튼(비로그인 시 로그인 라우팅)
- [ ] 출근 캘린더 영역(읽기 전용 최소 구현)

### 5-6. 체크인
- [ ] 카페 선택
- [ ] 날짜 선택
- [ ] 위치 인증
- [ ] 메모 작성
- [ ] 방문 등록 및 타임라인 반영(비로그인 시 로그인 라우팅)

### 5-7. 리뷰
- [ ] 방문 인증 사용자만 작성 가능
- [ ] 별점/내용/이미지 등록
- [ ] 최신순 목록/좋아요 수 표시
- [ ] 리뷰 작성/삭제/좋아요는 로그인 필요(비로그인 시 로그인 라우팅)

### 5-8. 마이 페이지
- [ ] 프로필/레벨/총 방문 수
- [ ] 방문 기록
- [ ] 즐겨찾기 카페
- [ ] 팔로우 메이드/배지 섹션 자리 확보
- [ ] 비로그인 마이페이지 진입 차단 + 로그인 성공 후 복귀

## 6. Phase 2 WBS (팬 기능)
- [ ] 메이드 팔로우/언팔로우
- [ ] 출근/생일/이벤트 알림
- [ ] 주간 출근 캘린더
- [ ] 메이드/카페 랭킹(주간/월간, 지역 필터)
- [ ] 스탬프/배지/레벨 시스템

## 7. Phase 3 WBS (운영 고도화)
- [ ] Admin 콘솔(승인/신고/밴)
- [ ] Owner 대시보드(카페/메이드/공지/출근표/통계)
- [ ] 광고/상단 고정/수수료 기능
- [ ] 글로벌 확장(한국→일본) 다국가 운영 정책

## 8. 테스트/QA 체크리스트
- [ ] 도메인 유스케이스 단위 테스트
- [ ] Repository 계약 테스트
- [ ] 화면 스모크 테스트(탭 이동/상세 진입/체크인)
- [ ] 권한 룰 시나리오 테스트(USER/OWNER/ADMIN)
- [ ] 성능 점검(목록 페이지네이션, 이미지 로딩)

## 9. 일정 체크리스트(8주)
- [ ] 1주차: 요구사항/스키마/권한 정책 확정
- [ ] 2주차: 인증/도메인/리포지토리 뼈대
- [ ] 3주차: 홈/탐색/카페상세
- [ ] 4주차: 메이드상세/리뷰/즐겨찾기
- [ ] 5주차: 체크인/위치 인증/방문 기록
- [ ] 6주차: 팔로우/알림/출근표
- [ ] 7주차: 랭킹/스탬프/배지
- [ ] 8주차: 안정화/QA/배포 준비

## 10. 완료 정의(Definition of Done)
- [ ] MVP 핵심 플로우가 Android/iOS/Desktop에서 동일 동작
- [ ] 앱 첫 실행 시 홈 진입, 마이 페이지 진입 시 비로그인이면 로그인 라우팅
- [ ] 로그인 후 앱 재실행 시 로그인 상태가 유지됨
- [ ] 로그인 필요 기능(즐겨찾기/팔로우/체크인/리뷰/좋아요/알림)은 모두 라우트 가드가 적용됨
- [ ] 리뷰 작성은 방문 인증 조건을 반드시 충족
- [ ] 역할 기반 권한 위반 요청이 모두 차단
- [ ] 주요 화면 로딩/전환이 목표 성능 기준 충족
- [ ] 운영 문서(스키마/룰/릴리즈 노트) 최신화

## 11. 구현 전 최종 점검 (추가 반영)
- [ ] 환경 분리 정책 확정: dev/staging/prod Firebase 프로젝트 분리
- [ ] 시크릿 관리 정책 확정: API 키/서비스 계정 키 저장소 및 노출 방지 규칙
- [ ] Firestore/Storage 보안 규칙 테스트 자동화 방식 확정
- [ ] Cloud Functions 배포/롤백 절차 확정
- [ ] 개인정보/운영 정책 확정: 계정 삭제, 데이터 보존 기간, 신고 처리 정책
- [ ] 관측 지표 확정: Crash 리포팅, 핵심 이벤트(체크인 성공률/리뷰 전환율) 수집 항목
- [ ] 성능 기준 수치화: 초기 로딩 시간, 목록 스크롤 지표, 이미지 용량 기준
- [ ] 딥링크/푸시 진입 시 로그인 가드 동작 규칙 검증
- [ ] 오프라인/네트워크 불안정 시 UX 정책 확정(재시도, 캐시, 메시지)
- [ ] 브랜치/릴리즈 정책 확정: develop-main 머지 기준, 태그/릴리즈 노트 규칙
